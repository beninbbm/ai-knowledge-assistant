# AI Knowledge Assistant

A local RAG (Retrieval-Augmented Generation) assistant: upload PDFs, Word documents and
Markdown, then ask questions and get answers with citations to the source passages.

Stack: FastAPI · Postgres + pgvector · Ollama (local LLM + embeddings) · React.

## One-time setup

```bash
brew install uv ollama
brew services start ollama
ollama pull llama3.1:8b
ollama pull nomic-embed-text
cp .env.example .env            # then set JWT_SECRET
```

## Run

```bash
docker compose up -d --wait     # Postgres + pgvector
cd backend
uv sync                          # install Python dependencies
uv run alembic upgrade head      # create/upgrade database tables
uv run uvicorn app.main:app --reload
```

In a second terminal, start the ingestion worker (it processes uploaded documents):

```bash
cd backend
uv run python -m app.ingestion.worker
```

Check http://localhost:8000/health. Interactive API docs: http://localhost:8000/docs.

## Web app

With the API and worker running, start the frontend in a third terminal:

```bash
cd frontend
npm install        # first time only
npm run dev        # http://localhost:5173
```

Sign up, upload documents on the **Documents** page, then ask questions on **Chat**.
Click a numbered citation to see the passage it came from. Admins also get a **Groups**
page for sharing documents with teams.

## Accounts

Anyone can sign up via `POST /auth/register`, but admins (who manage groups) can only be
created from the command line:

```bash
cd backend
uv run python -m scripts.create_user you@example.com --admin   # prompts for a password
```

In the API docs, click **Authorize** and log in with your email and password to try the
protected endpoints.

## Documents

Upload `.pdf`, `.docx` or `.md` files (max 25 MB) with `POST /documents`. The upload
returns immediately with status `pending`; the worker then extracts the text, splits it
into chunks and marks it `ready` (or `failed` with an error). See a document's chunks
with `GET /documents/{id}/chunks`.

Sample files for a fictional company live in `samples/` (regenerate with
`uv run python -m scripts.make_samples`). To see how any file gets chunked, without the
database:

```bash
cd backend
uv run python -m scripts.inspect_chunks ../samples/travel-expense-policy.pdf --sections
uv run python -m scripts.inspect_chunks ../samples/travel-expense-policy.pdf --target 150 --overlap 30
```

## Search

Each chunk is embedded with Ollama (`nomic-embed-text`) when it's processed. `GET /search?q=`
runs hybrid search (meaning + keywords) over the documents you can read. From the
terminal, showing how each result was found:

```bash
cd backend
uv run python -m scripts.search "how long is parental leave?" --as you@example.com
```

Documents processed before embeddings existed, or with a different `EMBED_MODEL`, can be
re-queued with `uv run python -m scripts.reindex` (add `--all` to redo everything).

## Asking questions

`POST /ask` returns an answer grounded in your documents, with numbered citations that
are checked against the passages the model was given. `POST /ask/stream` streams the same
answer as Server-Sent Events (`sources`, then `token`s, then `done`). `GET /chunks/{id}`
shows a cited passage with its neighbouring text.

From the terminal (add `--show-prompt` to see exactly what the model reads):

```bash
cd backend
uv run python -m scripts.ask "Can I carry over unused annual leave?" --as you@example.com
```

Answers are generated by `CHAT_MODEL` (default `llama3.1:8b`) with an 8,192-token context
window (`CHAT_NUM_CTX`). Expect a few seconds before the first word while the model reads
the retrieved passages.

## Conversations

Create a conversation with `POST /conversations`, then send questions with
`POST /conversations/{id}/messages` (streams like `/ask/stream`). Follow-up questions
such as "what about contractors?" are rewritten into standalone questions for searching
(sent as a `rewritten` event and saved as `standalone_query`), while the model answers
the original question with the last 3 turns as context. `GET /conversations/{id}` returns
the history with citations; a cited passage is only shown while you can still read its
document.

## Tests

```bash
cd backend
uv run pytest                        # all tests (needs Postgres and Ollama)
uv run pytest -m "not integration"   # skip tests that call the real Ollama models
uv run ruff check .      # lint
```

Frontend:

```bash
cd frontend
npm test           # unit tests (Vitest)
npm run lint       # oxlint
npm run e2e        # browser tests (Playwright): needs the API, worker and Ollama running
```

The first `npm run e2e` needs a browser: `npx playwright install chromium`.
